ของที่ต้องมี

สิ่งของรายละเอียด
บอร์ด Cytron ROBO ESP32พร้อมมอเตอร์สองตัวประกอบเป็นรถแล้ว
สาย USBต้องเป็นสายที่ส่งข้อมูลได้ สายชาร์จไฟอย่างเดียวใช้ไม่ได้ (เป็นปัญหาที่เจอบ่อยที่สุด)
แบตเตอรี่ใส่เมื่อจะปล่อยรถวิ่งจริง ตอนเขียนโปรแกรมใช้ไฟจาก USB ได้
โทรศัพท์มือถือเครื่องไหนก็ได้ที่ต่อ WiFi และเปิดเบราว์เซอร์ได้
เซอร์โว / เซนเซอร์ HC-SR04ไม่บังคับ — ไม่มีก็เรียนถึงด่าน 5 ได้ครบ

ลงสองอย่างนี้ก่อน

  1. ไดรเวอร์ CP210x — ตัวแปลง USB บนบอร์ดต้องมีไดรเวอร์ ไม่งั้นคอมพิวเตอร์จะมองไม่เห็นบอร์ดเลย แตกไฟล์ CP210x_Windows_Drivers.zip แล้วติดตั้ง จากนั้นรีสตาร์ตเครื่องหนึ่งครั้ง (ลงครั้งเดียวต่อเครื่อง)
  2. โปรแกรม MicroBlocks — ดาวน์โหลดจาก microblocks.fun เลือกรุ่นที่ตรงกับระบบปฏิบัติการ ใช้ได้ทั้ง Windows, macOS, Linux, Chromebook และมีแบบเปิดผ่านเบราว์เซอร์
  3. ไฟล์โปรเจกต์ — ดาวน์โหลด RoboCar.ubp เก็บไว้ในเครื่อง ไฟล์นี้มีทั้งโปรแกรมและไลบรารีครบในตัว

✅ ผ่านด่านนี้เมื่อ: เปิดโปรแกรม MicroBlocks ขึ้นมาได้ และมีไฟล์ RoboCar.ubp อยู่ในเครื่องแล้ว

ด่าน 1เชื่อมต่อบอร์ดครั้งแรก

เป้าหมาย: สั่งให้ไฟบนบอร์ดติดได้ด้วยการคลิกบล็อกเดียว — ยังไม่ต้องเขียนโปรแกรม

  1. เสียบสาย USB จากบอร์ดเข้าคอมพิวเตอร์ แล้วเปิดสวิตช์บอร์ด ไฟเล็ก ๆ บนบอร์ดควรติด
  2. เปิดไฟล์ RoboCar.ubp ด้วยเมนู File → Open ในโปรแกรม MicroBlocks
  3. กดปุ่มรูปสาย USB ที่แถบเครื่องมือด้านบน แล้วเลือกพอร์ตของบอร์ด (มักขึ้นชื่อว่า COM ตามด้วยตัวเลขบน Windows) เมื่อเชื่อมต่อสำเร็จจะมีวงกลมสีเขียวขึ้นข้าง ๆ
  4. ทดสอบ — ลากบล็อก KSU LED number 3 on มาวางบนพื้นที่ทำงาน แล้วคลิกที่ตัวบล็อกโดยตรง ไฟดวงที่ 3 ต้องติดทันที

เทคนิคสำคัญของ MicroBlocks: คลิกบล็อกไหนบล็อกนั้นทำงานทันที ไม่ต้องกดรันทั้งโปรแกรม ใช้ลองของทีละชิ้นได้เร็วมาก ลองคลิก KSU horn ดูก็ได้ ต้องมีเสียงแตรออกลำโพงบนบอร์ด

ถ้าหาพอร์ตไม่เจอ: ยังไม่ได้ลงไดรเวอร์ CP210x · ยังไม่ได้รีสตาร์ตหลังลงไดรเวอร์ · หรือใช้สาย USB แบบชาร์จไฟอย่างเดียว ลองเปลี่ยนสายก่อนเป็นอันดับแรก

✅ ผ่านด่านนี้เมื่อ: คลิกบล็อกแล้วไฟติดหรือมีเสียงออกจากบอร์ดได้

ด่าน 2โปรแกรมแรก — สามบล็อก

เป้าหมาย: ทำให้บอร์ดปล่อยสัญญาณ WiFi ของตัวเองและพร้อมรับคำสั่ง

แต่ละบล็อกทำอะไร

บล็อกหน้าที่

KSU start web controlเปิดสัญญาณ WiFi ชื่อ RoboCar พร้อมเว็บเซิร์ฟเวอร์ และตั้งค่าเริ่มต้นให้ทุกอย่าง

KSU do commandเอาคำนั้นไปทำให้จริง

ทำไมต้องมี forever? เพราะบอร์ดไม่รู้ว่าเราจะกดปุ่มเมื่อไร มันจึงต้องถามซ้ำ ๆ ตลอดเวลาว่า "มีคำสั่งเข้ามาหรือยัง" วินาทีละหลายสิบครั้ง ถ้าถามครั้งเดียวแล้วจบ กดปุ่มทีหลังก็จะไม่มีอะไรเกิดขึ้น

สั่งให้ทำงาน

  1. กดปุ่มเริ่มทำงาน ▶ ที่แถบเครื่องมือ (หรือคลิกที่สคริปต์ตรง ๆ ก็ได้)
  2. โปรแกรมถูกเก็บลงบอร์ดแล้ว ถอดสาย USB ได้เลย ใส่แบตเตอรี่แล้วเปิดสวิตช์ โปรแกรมจะเริ่มเองทุกครั้งที่เปิดเครื่อง

✅ ผ่านด่านนี้เมื่อ: เอาโทรศัพท์ไปค้นหา WiFi แล้วเห็นชื่อ RoboCar ขึ้นมาในรายการ

ด่าน 3ขับรถจากมือถือ

เป้าหมาย: บังคับรถให้วิ่งได้ครบสี่ทิศ

  1. ต่อ WiFi — ที่โทรศัพท์เลือกเครือข่าย RoboCar ใส่รหัสผ่าน robocar123
  2. เปิดเบราว์เซอร์ พิมพ์ http://192.168.4.1 ให้ครบทั้งบรรทัด อย่าให้เบราว์เซอร์เอาไปค้นหาใน Google
  3. หมุนโทรศัพท์เป็นแนวนอน — หน้าเว็บออกแบบมาสำหรับแนวนอนเท่านั้น ถ้าถือแนวตั้งจะขึ้นข้อความให้หมุนเครื่อง
  4. กดปุ่มลูกศร รถต้องวิ่งตามทันที ปล่อยนิ้วเมื่อไรรถหยุดเอง

เปิดจากคอมพิวเตอร์ก็ได้ ต่อ WiFi ชื่อเดียวกันแล้วเปิดหน้าเว็บ จากนั้นใช้ปุ่มลูกศรหรือปุ่ม W A S D บนแป้นพิมพ์บังคับรถได้เลย

รถวิ่งผิดทาง? แก้ตรงนี้

มอเตอร์แต่ละคันประกอบมาไม่เหมือนกัน ถ้าทิศทางไม่ตรง ให้คลิกบล็อก KSU set motor trim M1 -1 M2 -1 ด้วยค่าตามตารางนี้ (ค่าเริ่มต้นคือ -1 -1)

อาการใส่ค่า
กดเดินหน้าแล้วรถถอยหลัง และเลี้ยวสลับข้าง1 และ 1
กดเดินหน้าแล้วรถหมุนอยู่กับที่สลับแค่ตัวเดียว เช่น 1 กับ -1
เลี้ยวซ้ายกลายเป็นเลี้ยวขวาสลับทั้งสองตัว

ค่านี้จำได้จนกว่าจะปิดเครื่อง ถ้าเจอค่าที่ถูกแล้วให้ใส่บล็อกนี้ไว้ใต้ KSU start web control รถจะได้ถูกทิศทุกครั้งที่เปิด

ลองแท็บอื่นด้วย

✅ ผ่านด่านนี้เมื่อ: ขับรถได้ครบสี่ทิศ เปิดปิดไฟได้ และบีบแตรได้

ด่าน 4อ่านโค้ดให้ออก

เป้าหมาย: เข้าใจว่าการกดปุ่มบนมือถือกลายเป็นการหมุนล้อได้อย่างไร

เส้นทางของหนึ่งการกดปุ่ม

ขั้นเกิดอะไรขึ้น
1. นิ้วกดกดปุ่มลูกศรขึ้นบนหน้าเว็บ
2. มือถือส่งส่งข้อความสั้น ๆ ไปที่บอร์ดว่า /Forward
3. บอร์ดรับKSU web command อ่านได้คำว่า Forward
4. เก็บใส่กล่องคำนั้นถูกเก็บในตัวแปรชื่อ command
5. ตัดสินใจโปรแกรมเทียบว่าคำนี้ตรงกับอะไร แล้วสั่งมอเตอร์ให้หมุน

ตัวแปรคืออะไร

command คือกล่องใส่ของหนึ่งใบที่มีชื่อ เราหยิบคำที่ได้จากหน้าเว็บใส่ลงกล่องนี้ แล้วค่อยเปิดกล่องดูทีหลังว่าข้างในเป็นคำว่าอะไร ทุกรอบของลูป กล่องนี้จะถูกใส่ของใหม่ทับของเก่าเสมอ

ลองแกะบล็อกอัตโนมัติออก

ในไฟล์เฉลยมีสคริปต์ชุด if วางแยกไว้ข้าง ๆ ที่ไม่ได้ต่อกับอะไร วางไว้ให้ดูโดยเฉพาะ ลองเอา KSU do command ออกจากลูป แล้วเอาชุด if นี้ใส่แทน จะได้ผลเหมือนเดิมทุกอย่าง

set command to (KSU web command)

if (command) = 'Forward'  → KSU forward
if (command) = 'Backward' → KSU backward
if (command) = 'Left'     → KSU turn left
if (command) = 'Right'    → KSU turn right
if (command) = 'Stop'     → KSU stop
if (command) = 'Light1'   → KSU light (on)
if (command) = 'Light0'   → KSU light (off)
if (command) = 'Horn'     → KSU horn

อ่านออกเสียงได้ว่า "ถ้าในกล่องเป็นคำว่า Forward ก็ให้เดินหน้า" — แค่นั้นเอง ทั้งหมดคือเงื่อนไขเรียงกัน

ตัวพิมพ์ใหญ่-เล็กสำคัญมาก Forward ใช้ได้ แต่ forward กับ FORWARD ใช้ไม่ได้ คอมพิวเตอร์ถือว่าเป็นคนละคำกันคนละตัว

ลองเปลี่ยนดู: สลับให้ Forward ไปเรียก KSU backward แทน แล้วกดปุ่มขึ้นบนมือถือ — รถจะถอยหลัง นี่คือหลักฐานว่าปุ่มบนหน้าเว็บไม่ได้ผูกกับล้อโดยตรง แต่ผ่าน if ที่เราเขียนเอง เปลี่ยนได้ตามใจ

✅ ผ่านด่านนี้เมื่อ: ต่อ if ขึ้นมาเองจนขับรถได้ครบทุกทิศโดยไม่ใช้ KSU do command

อ่านตัวเลขออกมาด้วยบล็อก KSU command value แบบนี้

if (command) = 'Speed' → KSU set speed (KSU command value) %
if (command) = 'Servo' → KSU set servo (D4) to (KSU command value) degrees

จุดที่คนพลาดบ่อย: ถ้าคำสั่งล่าสุดไม่มีตัวเลขมาด้วย KSU command value จะรายงานเลข 90 ไม่ใช่ 0 (90 คือมุมกึ่งกลางของเซอร์โว) และต้องอ่านค่าในรอบเดียวกันกับที่คำสั่งเข้ามา เพราะรอบถัดไปค่าจะถูกคำสั่งใหม่ทับ

คำสั่งที่ส่งหลายค่า เช่น Rgb ที่ส่งมาสี่ตัว ให้ใช้ KSU command value # 1 โดยเปลี่ยนเลขในช่องเป็น 1, 2, 3, 4 เพื่อหยิบค่าทีละตัว

✅ ผ่านด่านนี้เมื่อ: เลื่อนแถบความเร็วบนมือถือแล้วรถวิ่งเร็ว-ช้าต่างกันจริง

ด่าน 6เซอร์โวและแขนกล

เป้าหมาย: สั่งให้แขนกลหมุนไปหยุดที่มุมที่ต้องการได้ · ต้องมีเซอร์โวอย่างน้อยหนึ่งตัว

เซอร์โวต่างจากมอเตอร์ยังไง

มอเตอร์ที่ขับล้อนั้นสั่งได้แค่ "หมุนแรงเท่าไร ทางไหน" มันหมุนวนไปเรื่อย ๆ ไม่รู้ว่าตัวเองอยู่ตรงไหน ส่วนเซอร์โวสั่งเป็นมุมได้เลยว่าให้ไปหยุดที่กี่องศา แล้วมันจะหมุนไปที่มุมนั้นและค้างอยู่อย่างนั้น จึงเหมาะกับแขนกล ที่คีบของ หรือหัวส่ายไปมา

180หมุนสุดไปอีกทางหนึ่ง

เสียบเซอร์โวตรงไหน

บอร์ดมีช่องเสียบเซอร์โว 4 ช่อง คือ D4 D5 D18 D19 ใช้พร้อมกันทั้งสี่ตัวได้ ถ้ามีตัวเดียวให้เสียบช่อง D4 ก่อน เพราะเป็นช่องที่แถบเลื่อนบนแท็บ DRIVE สั่งงาน

ระวังเสียบกลับด้าน — สายเซอร์โวมีสามเส้น ให้ดูสีเทียบกับที่พิมพ์ไว้บนบอร์ด โดยทั่วไปสีน้ำตาลหรือดำคือ GND · สีแดงคือไฟ · สีส้มหรือเหลืองคือสายสัญญาณ เสียบสลับขั้วอาจทำให้เซอร์โวเสียได้

ใส่แบตเตอรี่ด้วย เซอร์โวกินไฟมากกว่าที่คิด โดยเฉพาะตอนยกของหรือถูกฝืน ถ้าจ่ายไฟจากสาย USB อย่างเดียวแล้วบอร์ดรีเซ็ตตัวเองบ่อย ๆ ให้ใส่แบตเตอรี่แล้วลองใหม่

ทดสอบด้วยการคลิกบล็อกเดียว

ลากบล็อกนี้มาวางแล้วคลิกที่ตัวบล็อก เปลี่ยนตัวเลขเป็น 0, 90, 180 สลับกันดู แขนต้องขยับไปหยุดตามที่สั่ง

KSU set servo (D4) to (90) degrees

ถ้ามีตัวเดียวที่ช่อง D4 ใช้บล็อกทางลัดชื่อ KSU set arm angle 90 degrees ก็ได้ผลเหมือนกันทุกอย่าง แค่พิมพ์สั้นกว่า

ทำไมเป็น 0 ถึง 180? บล็อกดั้งเดิมของ Cytron ใช้ตัวเลข −90 ถึง 90 ซึ่งมีเลขติดลบให้สับสน ไลบรารีนี้จึงแปลงให้เหลือ 0–180 ที่จุดเดียว ทั้งหน้าเว็บและทุกบล็อกในไลบรารีใช้ 0–180 เหมือนกันหมด

สั่งจากมือถือ

แถบเลื่อนคำสั่งที่ส่งคุมเซอร์โวช่อง
SERVO บนแท็บ DRIVE/Servo_90D4
D4 บนแท็บ MORE/Servo_90D4
D5 บนแท็บ MORE/ServoB_90D5
D18 บนแท็บ MORE/ServoC_90D18
D19 บนแท็บ MORE/ServoD_90D19

ถ้าใช้ KSU do command อยู่แล้ว ทั้งห้าแถบนี้ทำงานได้เลยโดยไม่ต้องเขียนอะไรเพิ่ม แต่ถ้าเขียน if เองต้องดักคำสั่งแบบนี้

if (command) = 'Servo' → KSU set servo (D4) to (KSU command value) degrees

ให้แขนกวาดไปมาเอง

คลิกสคริปต์นี้ดู แขนจะกวาดกลับไปกลับมาสามรอบ

repeat 3 {
    KSU set arm angle (30) degrees
    wait 400 millisecs
    KSU set arm angle (150) degrees
    wait 400 millisecs
}
KSU set arm angle (90) degrees

ทำไมต้องมี wait คั่น? เพราะการสั่งมุมใช้เวลาเสี้ยววินาที แต่แขนต้องใช้เวลาเดินทางจริง ถ้าสั่งมุมใหม่ทันทีโดยไม่รอ แขนจะยังไปไม่ถึงมุมเดิมแล้วถูกสั่งให้กลับ ผลคือมันสั่นอยู่กับที่แทนที่จะกวาด

อย่าฝืนเซอร์โว ถ้าได้ยินเสียงครืดคราดค้างอยู่ แปลว่าแขนไปชนอะไรเข้าหรือถูกสั่งเกินมุมที่กลไกไปได้ ให้รีบสั่งกลับมาที่ 90 องศา ปล่อยค้างไว้นาน ๆ เฟืองข้างในจะหักได้

ต่อยอด: ใช้เซอร์โวสองตัว ตัวหนึ่งเป็นข้อต่อยกขึ้นลง อีกตัวเป็นก้ามคีบ แล้วเขียนคำสั่ง "คีบ" ที่สั่งสองตัวต่อกันเป็นลำดับ — เอาไปทำภารกิจเก็บของแข่งกันในห้องได้เลย

✅ ผ่านด่านนี้เมื่อ: เลื่อนแถบ SERVO บนมือถือแล้วแขนขยับตามนิ้วได้

ด่าน 7ใส่เซนเซอร์ให้รถหยุดเองก่อนชน

เป้าหมาย: รถตัดสินใจเองได้โดยไม่ต้องรอคำสั่งจากมือถือ · ต้องมีเซนเซอร์ HC-SR04

ต่อสายแบบนี้

ขาเซนเซอร์ต่อเข้ากับ
VCC5V
GNDGND
Trigขา 33
Echoขา 32

ต่อตามนี้แล้วไม่ต้องเพิ่มบล็อกตั้งค่าใด ๆ เพราะ KSU start web control ตั้งค่านี้ไว้ให้แล้ว ลองคลิกบล็อก KSU distance cm ดู ต้องได้ตัวเลขระยะห่างเป็นเซนติเมตร

ขา 33 กับ 32 คือ LED ดวงที่ 8 และ 7 ไฟสองดวงนี้จะกะพริบตามจังหวะยิงคลื่นซึ่งไม่เป็นไร แต่อย่าสั่งเปิด LED 7 หรือ 8 จากแท็บ LIGHT ขณะเสียบเซนเซอร์ เพราะจะแย่งกันคุมสายเส้นเดียวกัน

ใส่สมองให้รถ

วางชุดบล็อกนี้ในลูป forever ต่อจาก KSU do command

set cm to (KSU distance cm)
if (cm > 0) and (cm < 20) {
    KSU stop
    KSU beep
}

ทำไมต้องเช็ก cm > 0 ด้วย? เพราะเลข 0 แปลว่า "ไม่มีเสียงสะท้อนกลับมา" ซึ่งเกิดตอนที่ข้างหน้าโล่งไม่มีอะไรเลย ถ้าไม่ใส่เงื่อนไขนี้ รถจะหยุดตอนที่ทางโล่ง แต่กลับวิ่งชนตอนมีสิ่งกีดขวาง — ตรงข้ามกับที่ต้องการทุกประการ

อ่านค่าครั้งเดียวต่อหนึ่งรอบ — เก็บใส่ตัวแปร cm ก่อน แล้วค่อยเอาตัวแปรไปเทียบ การเรียกบล็อกวัดระยะซ้ำ ๆ ในรอบเดียวจะทำให้รถตอบสนองช้าลงอย่างเห็นได้ชัด เพราะการยิงคลื่นแต่ละครั้งหน่วงลูปได้ถึง 25 มิลลิวินาที

✅ ผ่านด่านนี้เมื่อ: เอามือไปบังหน้ารถแล้วรถหยุดพร้อมส่งเสียงเตือน

ด่าน 8เป็น Hero — สร้างคำสั่งของตัวเอง

เป้าหมาย: เพิ่มปุ่มใหม่บนหน้าเว็บที่สั่งให้รถทำท่าที่เราออกแบบเอง

ถึงตรงนี้คุณใช้ของที่คนอื่นทำไว้ได้คล่องแล้ว ด่านสุดท้ายคือการเพิ่มของใหม่เข้าไปเอง ซึ่งต้องแก้ 3 จุดพร้อมกัน ขาดจุดใดจุดหนึ่งคำสั่งจะเงียบหายไปโดยไม่มีข้อความแจ้งเตือนอะไรเลย

จุดที่ 1 · หน้าเว็บต้องส่งคำนั้น

เพิ่มปุ่มในไฟล์ RoboCar-Control.html โดยให้เรียกผ่านฟังก์ชัน s("Dance") เท่านั้น

จุดที่ 2 · ไลบรารีต้องรู้จักคำนั้น

เพิ่มเงื่อนไขในบล็อกลับชื่อ _do2 ห้ามเพิ่มใน KSU do command เพราะจะเกินขีดจำกัด 1000 ไบต์

จุดที่ 3 · ถ้าต้องมีบล็อกใหม่

เพิ่มบรรทัด spec ในไลบรารี เพื่อให้บล็อกโผล่มาในแถบเครื่องมือให้ลากใช้ได้

อย่าลืมว่าไลบรารีมีสองสำเนา — การแก้จะสมบูรณ์ก็ต่อเมื่อลงทั้งใน KSU_RoBoESP32.ubl และสำเนาที่ฝังอยู่ใน RoboCar.ubp เพราะไฟล์หลังคือไฟล์ที่โหลดลงบอร์ดจริง แก้แค่ไฟล์แรกไฟล์เดียวจะไม่มีอะไรเปลี่ยนเลย รายละเอียดอยู่ในคู่มือไลบรารี

ทำแบบไม่ต้องแตะไลบรารีก็ได้

ถ้ายังไม่อยากยุ่งกับไฟล์ไลบรารี ใช้วิธีง่ายกว่านี้ได้: เอาปุ่มที่มีอยู่แล้วมาใช้ใหม่ เช่น จับ Horn ให้ทำท่าเต้นแทนการบีบแตร โดยเขียน if ของตัวเองในสคริปต์หลัก

if (command) = 'Horn' {
    repeat 3 {
        KSU turn left
        KSU set RGB (all) red (255) green (0) blue (0)
        wait 200 millisecs
        KSU turn right
        KSU set RGB (all) red (0) green (0) blue (255)
        wait 200 millisecs
    }
    KSU stop
}

ต้องเอา KSU do command ออกก่อน ไม่งั้นมันจะบีบแตรแข่งกับท่าเต้นของเรา

🏆 จบคอร์สเมื่อ: กดปุ่มบนมือถือแล้วรถทำท่าที่คุณออกแบบเองได้
